#### Detailed Back-Stack & Navigation Rules:

1. **Safe Pop Guard (`safePopBackStack()`)**:
   - Implemented in [`PennyWiseNavHost.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/navigation/PennyWiseNavHost.kt#L36-L40): Prevents rapid double-tap back presses from causing back-stack corruption or screen overlap by asserting `currentBackStackEntry?.lifecycle?.currentState == Lifecycle.State.RESUMED`.
2. **Bottom Navigation Back Handler**:
   - Implemented in [`MainScreen.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/ui/MainScreen.kt#L88-L97): `BackHandler(enabled = !isHomeScreen)` intercepts back presses on any non-Home tab (`transactions`, `subscriptions`, `analytics`, `chat`) or nested screens inside `MainScreen` and redirects navigation back to `home` with `saveState = true`, `launchSingleTop = true`, and `restoreState = true`.
3. **AppLock Transition**:
   - Implemented in [`PennyWiseApp.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/PennyWiseApp.kt#L106-L121) & [`PennyWiseNavHost.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/navigation/PennyWiseNavHost.kt#L63-L73): When app is locked on resume, `navController.navigate(AppLock)` is triggered with `popUpTo(startDestinationId) { inclusive = false }`. Unlocking pops `AppLock` inclusively and restores `Home`.
4. **Onboarding Completion Transition**:
   - Implemented in [`PennyWiseNavHost.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/navigation/PennyWiseNavHost.kt#L75-L87): On completing onboarding, `navController.navigate(Home) { popUpTo(OnBoarding) { inclusive = true } }`, permanently removing onboarding from the back-stack.

## 3. Stored But Never Surfaced

The following fields and tables are persistently stored in Room (and backed up locally) but are **never or under-surfaced in the UI**. They represent significant untapped potential for local privacy-first user features.

### Rank 1: Automated Rule Hit Counts & Application Audit History (`rule_applications` table)
- **File Paths**: [`RuleApplicationEntity.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/data/database/entity/RuleApplicationEntity.kt), [`RuleApplicationDao.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/data/database/dao/RuleApplicationDao.kt), [`RulesScreen.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/ui/screens/rules/RulesScreen.kt).
- **What is Stored**: Every time a custom or system rule auto-categorizes or rewrites transaction fields during SMS parsing, `RuleApplicationEntity` inserts a record containing `rule_id`, `rule_name`, `transaction_id`, `fields_modified` (JSON array of changed keys), and `applied_at` timestamp.
- **Current UI Gap**: [`RulesScreen.kt`](file:///D:/New%20folder/pennywiseai-tracker/app/src/main/java/com/pennywiseai/tracker/ui/screens/rules/RulesScreen.kt) only lists rules and their active/inactive toggles. It shows **no hit counts** (e.g. "Applied 42 times"), **no last-applied timestamp**, and **no execution log** showing which exact transactions were modified by a rule.
- **Unlockable User Value**: 
  - **High**: Displays rule utility metrics (identifying inactive or dead rules).
  - Allows users to tap a rule to view all transactions modified by that rule.
  - Enables a single-tap "Undo rule application" or "Rollback rule changes" for misconfigured rules.

Unparsed or missed push notifications remain completely invisible to the user.
- **Unlockable User Value**:

  - Allows users to convert unparsed app notifications directly into custom parsing templates or transactions.

## 5. UX Friction

A walkthrough of common user journeys reveals several areas of friction, excessive tapping, and navigational confusion.

### 5.1 Journey Analysis & Tap Counts

| Action | Tap Count | Friction / Confusion Point |
|---|---|---|
| **First run + SMS permission** | ~8-9 taps | The `SmsScanStep` blocks the user. If they have 10k+ SMS, they must wait minutes or hit "Skip". If parsing yields 0 results, there is no explanation (unsupported bank). If permission is denied, the user lands on a completely blank Home screen with no onboarding empty states. |
| **Seeing today's spend** | 1-2 taps | Home screen defaults to current month Cash Flow. To see "Today", the user must navigate to Analytics or filter the Transactions tab. |
| **Fixing a wrong category** | 4 taps | Requires tapping into `TransactionDetailScreen`, opening the category picker sheet, selecting, and returning. No inline category editing in the list. |
| **Searching a past transaction** | 2 taps + typing | Accessible via the Transactions tab search icon. Standard friction. |
| **Creating a budget** | 4 taps + typing | Buried in `Settings` -> `Manage Budgets`. Highly undiscoverable for a core feature. |
| **Checking subscriptions** | 1 tap | Requires finding the `UpcomingSubscriptionsCard` on the Home screen and tapping "View All". Not accessible via bottom navigation. |
| **Checking an account balance** | 0-1 taps | Visible on Home `AccountCarousel`, or 1 tap to `ManageAccountsScreen` if off-screen. |
| **Exporting data** | 4 taps | `Settings` -> `Export Data` -> System file picker. |

### 5.2 Top 10 Highest-Impact Improvements (Ordered)

1. **Empty States with CTAs:** Introduce clear illustrations and actions on Home and Transactions when there is no data (or permission was denied), rather than showing blank screens.
2. **Needs Review Inbox:** Provide visibility for unparsed or low-confidence SMS. Currently, users have no idea if an SMS failed to parse unless they dig into the Unrecognized SMS debug screen.
3. **Background the Onboarding SMS Scan:** Allow users to enter the app immediately while historical SMS scanning happens in the background via WorkManager, rather than blocking the onboarding flow.
4. **Promote Budgets out of Settings:** Move Budget creation and tracking to the Home screen or bottom navigation to improve discoverability.
5. **One-Tap Category Fix:** Allow users to change a transaction's category directly from the Transactions list without opening the full detail screen.
6. **"Today's Spend" Visibility:** Add a clear "Today" summary metric to the top of the Home screen alongside the monthly cash flow.
7. **Global Period Switcher:** Implement a unified dropdown (Today, This Week, This Month) that applies globally across Home, Transactions, and Analytics.
8. **Clarify "0 Transactions" in Scan:** If the initial scan finds nothing, explicitly tell the user their bank may not be supported yet, and prompt them to add a custom template.
9. **Promote Subscriptions:** Give subscriptions a dedicated top-level view or clearer Home integration, as they are a primary use case.
10. **Separate Cards from Accounts in Net Worth:** Make the distinction between cash assets (banks) and credit liabilities (cards) clearer in the global balance math.
